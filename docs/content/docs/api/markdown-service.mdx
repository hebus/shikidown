---
title: MarkdownService
description: The root-provided service behind the component and the pipe — use it directly for headless rendering.
---

`MarkdownService` is `@Injectable({ providedIn: 'root' })`. It owns the markdown-it instance, the
Shiki highlighter and the block cache — which is why the cache is shared by every
`MarkdownComponent` in the application.

Inject it when you need HTML outside a template: pre-rendering, a custom pipe, a report generator,
an export to email.

```typescript
import { MarkdownService, type RenderedBlock } from 'shikidown';

@Injectable({ providedIn: 'root' })
export class ContentService {
  private readonly md = inject(MarkdownService);

  async toHtml(markdown: string): Promise<string> {
    return this.md.parseAsync(markdown);
  }

  async toBlocks(markdown: string): Promise<RenderedBlock[]> {
    return this.md.parseBlocksAsync(markdown);
  }
}
```

## Methods

| Method | Signature | Description |
|---|---|---|
| [`initialize`](#initialize) | `() => Promise<void>` | Loads Shiki and builds the markdown-it instance. |
| [`parseAsync`](#parseasync) | `(content: string) => Promise<string>` | Renders the whole document, returns raw HTML. |
| [`parse`](#parse) | `(content: string) => string` | Synchronous render. Throws before initialisation. |
| [`parseBlocksAsync`](#parseblocksasync) | `(content: string) => Promise<RenderedBlock[]>` | Renders as independent blocks, with LRU caching. |
| [`renderBlocksAsync`](#renderblocksasync) | `(content: string, options?: BlockRenderOptions) => Promise<BlockRenderResult>` | Block rendering for streamed documents: re-parses only the end. |
| [`getStats`](#getstats) / `resetStats` | `() => MarkdownStats` / `() => void` | Work counters — parses, renders, highlights, cache hits. |
| [`clearCache`](#clearcache) | `() => void` | Empties the block and highlight caches. |

---

### initialize

```typescript
initialize(): Promise<void>
```

Dynamically imports Shiki, creates the highlighter with the configured themes and languages, builds
the markdown-it instance, resolves and applies your plugins, and installs the `mermaid` fence rule.
Plugins declared as `{ load: () => import('…') }` are fetched here, in parallel, before any of them
is applied.

Idempotent, and safe to call concurrently — the promise is memoised, so parallel callers share one
initialisation. Every async method calls it for you; you only need it explicitly before
[`parse()`](#parse).

<Callout type="info">
  **In a server environment no highlighter is created.** The document still renders, with code
  fences emitted as plain `<pre class="shiki"><code>` blocks.
</Callout>

### parseAsync

```typescript
parseAsync(content: string): Promise<string>
```

Renders the whole document and returns raw HTML — a `string`, not `SafeHtml`. Raw HTML in the
source has already been filtered according to `htmlPolicy` (see
[Content security](/docs/guides/security)); binding it through `DomSanitizer` would also strip
embedded Custom Elements and Shiki's inline styles, so use `bypassSecurityTrustHtml`.

---

### parse

```typescript
parse(content: string): string
```

Synchronous render. **Throws** if the service has not finished initialising:

```
[shikidown] MarkdownService not initialized. Call parseAsync() first.
```

Use it in code that cannot be asynchronous, after awaiting [`initialize()`](#initialize) once:

```typescript
await this.md.initialize();
const html = this.md.parse('# Now this is safe');
```

---

### parseBlocksAsync

```typescript
parseBlocksAsync(content: string): Promise<RenderedBlock[]>
```

Splits the document into independent root blocks and renders each one, serving unchanged blocks
from the LRU cache. This is what `MarkdownComponent` calls in incremental mode.

Each [`RenderedBlock`](/docs/api/types#renderedblock) carries the FNV-1a hash of its source text and
its raw HTML. The hash is a stable identity: use it as the tracking key if you drive your own
rendering loop.

```typescript
const blocks = await this.md.parseBlocksAsync(markdown);
// [{ hash: '1f4a3b2c', html: '<h1>Title</h1>\n' }, …]
```

See [Incremental rendering](/docs/guides/incremental-rendering) for what the pipeline buys you and
how to keep the DOM stable across renders.

---

### renderBlocksAsync

```typescript
renderBlocksAsync(content: string, options?: BlockRenderOptions): Promise<BlockRenderResult>
```

The pipeline behind `<shikidown [streaming]>`. Options:

- `previous` — the `state` returned by the previous call for the same document. When the beginning
  of the document is unchanged, only its last block is re-parsed.
- `streaming` — repairs the end of the document for display, and leaves an open code fence
  unhighlighted until it closes.
- `signal` — an `AbortSignal`; the call rejects if it is aborted before rendering starts.

The result is identical to a full parse, whatever the chunking — the state only saves work. See
[Streaming LLM output](/docs/guides/streaming#headless-use).

---

### getStats

```typescript
getStats(): MarkdownStats
resetStats(): void
```

Cumulative counters (`fullParses`, `tailParses`, `blockRenders`, `blockCacheHits`, `highlights`,
`highlightCacheHits`) — useful in tests to check that a fragment does not redo work.

---

### clearCache

```typescript
clearCache(): void
```

Empties the block cache. Needed after a **runtime theme change**, since blocks are keyed on source
text alone and would otherwise keep their old colours.

```typescript
this.md.clearCache();
```

A dark/light toggle does not require this: with a `{ dark, light }` theme pair both colour sets are
already present in the rendered HTML.

## Defaults

Values used when `provideMarkdown()` is absent, or when an option is not set:

| | Default |
|---|---|
| Theme | `{ dark: 'github-dark', light: 'poimandres' }` |
| Languages | 16 common languages — see [Configuration](/docs/configuration#languages) |
| markdown-it options | `{ html: true, linkify: true, typographer: true }` |
| HTML policy | `'sanitize'` |
| Block and highlight cache capacity | `256` each |
